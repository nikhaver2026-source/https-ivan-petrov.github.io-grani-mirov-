# Подпись APK постоянным ключом

## Зачем

Android и Play Protect узнают приложение по паре «имя пакета + ключ подписи».
Если ключ меняется от сборки к сборке, Android считает новую версию другим
приложением: она не ставится поверх прежней (старую приходится удалять), а
Play Protect видит незнакомое приложение и проверяет его при каждой установке.

Так и было до «Альфа 3.3»: сборка заводила ключ сама и хранила его только в
кэше GitHub Actions. Кэш стирается после недели без сборок — и следующая
сборка получала новый ключ. Задача `keepkey`, которая должна была освежать кэш
по расписанию, не срабатывала: GitHub запускает расписания только из основной
ветки, а этого рабочего процесса там нет.

Теперь ключ — постоянный, из секретов репозитория: один и тот же во всех
сборках, как у обычных приложений. Новые версии ставятся поверх прежних.

## Как задать ключ (один раз)

1. GitHub → репозиторий → Settings → Secrets and variables → Actions →
   New repository secret.
2. Имя `ANDROID_KEYSTORE_B64`, значение — хранилище ключа в base64
   (одна длинная строка).
3. Имя `ANDROID_KEYSTORE_PASS`, значение — пароль хранилища.
4. Необязательно: `ANDROID_KEY_ALIAS` — если псевдоним ключа не `lab`;
   `ANDROID_KEY_PASS` — если пароль ключа не совпадает с паролем хранилища.

Ключ можно сделать и самим (нужна только Java):

```sh
keytool -genkeypair -keystore lab.keystore -storetype PKCS12 \
  -alias lab -keyalg RSA -keysize 2048 -validity 10000 \
  -dname "CN=Podzemnaya Laboratoriya, O=Grani Mirov, C=RU"
base64 -w0 lab.keystore > ANDROID_KEYSTORE_B64.txt
```

## Как проверить

В журнале сборки шаг «Ключ подписи» пишет «Подпись: постоянный ключ из
секретов репозитория», а шаг «APK» — схемы подписи (v1, v2, v3) и отпечаток
сертификата (`certificate SHA-256 digest`). У всех сборок отпечаток должен
быть один и тот же.

Секрета нет — сборка подписывает запасным ключом из кэша и предупреждает об
этом в журнале. Секрет задан неверно (не тот пароль, испорчен base64) —
сборка падает сразу, а не выпускает APK без подписи.

## Важно

- Ключ и пароль — только в секретах репозитория и в надёжной копии у
  владельца. В репозиторий их не кладут, в чат и журналы не печатают.
- Потеряли ключ — новые версии тем же ключом не подписать: игрокам придётся
  один раз удалить игру и поставить заново.
- Первая сборка с новым постоянным ключом не встанет поверх версии,
  подписанной прежним ключом: старую игру нужно один раз удалить. Дальше
  каждая новая версия ставится поверх.
