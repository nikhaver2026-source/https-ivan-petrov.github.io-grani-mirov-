# Единая система взаимодействия «Грани Миров»

Документ описывает, как устроено взаимодействие игрока с миром после
переработки по брифу «Система звуковой навигации, жестов, инвентаря,
торговли и интерактивных объектов». Главный принцип: игрок не угадывает,
какой интерфейс предусмотрел разработчик — мир сам даёт логичный набор
действий по ситуации. Проверяется набором 104 (`tests/`); прежние свойства —
наборами 27, 29, 37, 41, 42, 68, 95, 97.

## 1. Режим полной звуковой игры

Настройка «Подсказки расположения объектов» (`settings.hintMode`):

| Режим | Что делает |
|---|---|
| `full` — полные | игра называет, что рядом, где оно и как подойти |
| `min` — минимальные | описания места и пространственные сведения режутся до первой фразы (`Speech._shape`), объекты — только по запросу |
| `sound` — только звуковая навигация | словесные подсказки о расположении выключены (`settings.hints=0`, распорядитель отбрасывает `desc` и `object`); мир слышен |

Старый ключ `settings.hints` выводится из режима, так что прежний код читает
его как раньше. В режиме звука проходы слышны ветром с их стороны
(`passageCues`), дверь — петлёй, ступени — камнем, ворота — створкой; живая
звуковая картина `Scape` подаёт голоса колодца, горна, алтаря, лавки, книг,
тварей и жителей с их сторон (`SCAPE_TILE`, `SCAPE_VOICE`). У каждого
источника — сторона, расстояние, высота, громкость с затуханием, отзвук
места (`Room`) и преграды стен (`Spatial.occlusion`). Тварь и житель
звучат шагом, дыханием и делом со своей стороны.

## 2. Осмотр

`Look` (модуль `LOOK`), три пальца влево. Сторона взгляда — сторона
последнего шага (`lastMoveDir`). `Look.scan()` находит объекты, жителей,
двери, проходы, лестницы, ресурсы, находки, обозы, узлы сети, ловушки и
тварей; каждому — сектор относительно взгляда (`впереди`, `слева`,
`справа`, `позади`, `здесь`), опасное — первым. `Look.summary()` говорит
коротко: что, сторона, шаги. Окно осмотра — список; двойное касание по
объекту — `Look.select()`: под рукой (по прямой, не по диагонали) сразу
открываются его действия, дальше объект становится целью (`Look.target`).

## 3. Жесты

Все касания идут через один диспетчер (`touchstart`, `touchmove`,
`touchend`), один обработчик кликов и один клавиатуры — набор 104
пересчитывает их в исходнике. Опись жестов — таблица `GESTURE_MAP`
(модуль `Gestures`): число пальцев решает первым, у каждой записи — род,
сторона, где действует и приоритет; `Gestures.conflicts()` пуст. Окно
«Жесты» читает эту же таблицу.

- Два пальца вниз — `Look.interact()`: цель под рукой → её действия; цель
  дальше → направление, шаги и маяк; цели нет → `useHere()`.
- Два пальца вверх — повторить последнее; если речь идёт — оборвать
  (`Speech.isSpeaking` → `stop`, иначе `repeatLast`); два запуска речи не
  складываются.
- Два пальца влево — карта места, и снаружи тоже: сетка семь на семь и
  «Известные точки» (`mapPoints`) — двери, лестницы, жители, сундуки внутри;
  города, постройки, подземелья, цели дел, узлы сети, крепости, зал Дома
  снаружи; касание точки — маяк с её стороны. Тот же жест закрывает.
- Два пальца вправо — журнал дел по разделам: активные, готовые к сдаче,
  выполненные, проваленные, цепочки, скрытые; у дела — цель
  (`qProgressText`), этап, указания, награда, последствия
  (`questConsequences`). Тот же жест закрывает.
- Касание игрового поля одним пальцем — одиночное или двойное — ничего не
  делает: сбор — касание двумя пальцами, действие здесь — два пальца вниз.

## 4. Инвентарь

Три пальца вниз. Двадцать один раздел (`INV_CATS`): оружие, щиты, броня,
шлемы, перчатки, обувь, аксессуары, артефакты, сокровища, магические
предметы, свитки, книги, зелья, ресурсы, материалы, квестовые предметы,
инструменты, боеприпасы, еда, ингредиенты, прочие предметы. Окно открывается
списком разделов, раздел — двойным касанием (см. «Настройки и инвентарь —
пунктами»). Раздел вещи решают правила
`INV_CAT_RULES` по порядку (`invCategoryOf`); хранилище сохранения (`G.gear`,
`G.items`, `G.inv`, `G.potions`, `G.artifacts`, `G.comps`) на раздел не
влияет. `Inventory.registerRule(cat,re)` и `Inventory.registerCat(id,n,з)`
расширяют разбор без правки кода.

Карточка (`invBrief`): имя, род («одноручное оружие», «щит», «доспех»…),
урон или защита, состояние в сотых (`itemCondition`, поле `сост`),
требование силы (`itemStrReq`), ранг и качество, надето ли, чары, руна,
освящение, яд, клеймо, улучшения. Бой снимает состояние (`gearWear` в
`victory`), наковальня возвращает.

## 5. Действия вещи

Реестр `ITEM_ACTIONS` (`iaction(id,{n,значок,cats,можно,делать})`). `можно`
возвращает `true` или причину словами; `invActionsAll(row)` даёт доступное
и недоступное с причиной, окно показывает оба списка (недоступных — не
больше восьми, сперва те, что упираются не в место). Контекст — `invContext()`:
станки рядом (`objectsHere` с полем `станок`), алтарь (`altarAt`),
торговец, житель, ночь.

| Раздел | Действия | Контекст |
|---|---|---|
| снаряжение | осмотреть, экипировать, снять, использовать, сравнить, состояние, продать, выбросить | наковальня/горн: ремонт (руда), улучшить (слиток, до трёх), закалить, заточить, перековать, клеймо, компонент, разобрать, ковать; круг/шар: зачаровать (кристалл); верстак/наковальня: руна (камень) |
| артефакты | осмотреть, изучить, активировать, деактивировать (спящий не действует — `ART.works`), настроить, способность (заряд), определить свойства, зарядить, зачаровать, починить, продать, выбросить | |
| ресурсы, материалы, ингредиенты | осмотреть, использовать, разделить стопку (на землю, `G.piles`), объединить, применить в ремесле (техники станка, берущие этот припас), продать, выбросить | чан: алхимия, смешать, эссенция, яд (грибы ×2), противоядие (трава ×2), очистить, исследовать состав; горн: плавить; наковальня: клинок; алтарь: дар, жертва |
| свитки, книги | осмотреть, прочитать, изучить, изучать главы, использовать для обучения (заклинание из книги), передать жителю, продать, выбросить | |
| зелья, еда | выпить, съесть, передать, продать, выбросить | |
| квестовые | осмотреть; выбросить и продать защищены — причина словами | алтарь: возложить реликвию |
| алтарь (любой раздел) | помолиться, обратиться к божеству, откровение (благосклонность ≥ 12), освятить (≥ 4), очистить, снять проклятие, особый ночной ритуал (≥ 20, ночь, артефакт) | |

«Выбросить»: вещь — «Выбросить «X»? Да / Нет»; стопка — «Выбросить сколько?
Одну / Несколько / Половину / Всю стопку / Нет». Квестовые предметы
защищены. Продажа из инвентаря — «Продать «X» за N золотых? Продать /
Отмена».

## 6. Интерактивные объекты

Одна архитектура: объект (`objectsHere`) → действия (`IACT`, `actionsFor`,
`actionsForAll` с причинами) → окно (`openObjActions`) → исполнитель
(`doObjAction`); всё это — модуль `Interact` (`INTERACTION`): `objects`,
`describe`, `actions`, `menu`, `run`, `why`, `register`. У действия — `можно`
и `почему`; область уместности причин — `IACT_SCOPE`. Помимо прежних
(осмотреть, прислушаться, постучать, пустота, отсек, тайники, ящик,
механизм двери, рычаг, сдвинуть, полка, техники станков, двенадцать
действий алтаря, ловушки) добавлены:

- дверь: открыть, закрыть, запереть, отпереть, ключ, взломать, чары,
  подслушать (что за створкой: `behindDoor`); запертая дверь держит шаг
  (`moveInside`);
- сундук: открыть, осмотреть содержимое (`chestPreview`), забрать всё,
  ключ, взломать; с третьего яруса часть сундуков заперта (`chestLocked`);
- шкаф и полка: найти книгу, читать, взять книгу (в раздел книг, `G.tomes`),
  перебрать полку, тайник, механизм;
- стол, конторка, комод, стойка: взять предмет, читать документы, ящик,
  тайник;
- колодец: набрать воды, бросить монету (удача), прислушаться, спустить
  верёвку;
- очаг и жаровня: отдохнуть, приготовить, зажечь факел;
- статуя: прочитать надпись; круг: встать в круг; лестница: спуститься или
  подняться, послушать вниз; прилавок: торговать, спросить цены; узел
  сети: сведения; постройка: войти, услуги, причал, скакун; ресурс: собрать.

Звук у каждого действия — записью (`doorSound`, `chestSound`, `bookSound`,
`altarSound`, банк ролей), со стороны объекта.

## 7. Торговля

Модуль `Trade` (`TRADE`), окно `modal-shop`, открывается из карточки
торговца («Торговля: купить и продать»), из меню действий («Торговля с
ближним торговцем») и с прилавка внутри стен. Два раздела: «Купить» —
`shopStockRows` из `stockFor` (специализация `MERCH_KINDS`, нрав, казна,
скрытый товар `merchDoors` с условием); «Продать» — `shopSellRows` из
инвентаря, что торговец согласен взять (`merchantBuys` по таблице
`MERCH_BUYS`: кузнец — оружие и металл, травник — травы и зелья, книжник —
книги и свитки, собиратель — артефакты; «берёт только своё» сужает,
«берёт краденое» расширяет; кошель торговца конечен). Пятнадцать
категорий (`SHOP_CATS`). Карточка: имя, категория, характеристики,
состояние, ранг, качество, цена, счёт, требование силы, доступность.
Сделка подтверждается: «Купить «X» ×N за M золотых? Купить / Отмена»;
стопки — счётом (1, 5, 10, на всё золото / всё). Старые кнопки прилавка в
карточке жителя остались как короткий путь.

## 8. Речь и субтитры

Один распорядитель речи (`Speech`): смена пункта обрывает старое
(`interrupt:true`), один и тот же элемент не называется дважды подряд,
меню читает доступное списком и число недоступного. Субтитры —
`settings.subMode`: `off`, `important` (события), `speech` (реплики),
`sounds` (и описания записей, `subSound`, раз в девять десятых секунды);
`sub(text,level)` — уровни `important`, `speech`, `sound`. Речь попадает в
субтитр из `Speech._speak` по приоритету. Субтитры не обязательны для
прохождения.

## 9. Критерий готовности

Найти объект по звуку → осмотреться (3←) → выбрать объект (двойное
касание) → контекстное меню (2↓ или сразу) → действия свайпом → выбрать
(двойное касание) → результат словом и звуком → назад в мир (2-пальцевое
касание закрывает). Инвентарь: 3↓ → раздел → вещь → карточка → действия
(свайп ↑/↓) → результат. Торговля: карточка торговца → «Торговля» →
«Купить» или «Продать» → категория → вещь → карточка и цена → сделка.
Объект: действие → проверка условий → выполнение или причина отказа.

## 10. Что проверяется автоматически и что — руками

Наборы 104, 27, 29, 37, 41, 42, 68, 95, 97 в настоящем браузере
проверяют: единственность обработчиков в исходнике, карту жестов без
споров, инертность касаний поля одним пальцем, работу жестов поверх окон,
речь без двойного озвучивания (один распорядитель, `speakTextOf` не
называет один элемент дважды), режим «только звук» (описания молчат,
проходы слышны), инвентарь и торговлю целиком, объекты с причинами отказа.

Руками, на устройстве, проверяются то, чего браузер без экрана не даёт:
1. Android с TalkBack и iOS с VoiceOver: жесты игры перехватываются в
   режиме прямого касания (настройка «Объявления VoiceOver и TalkBack» —
   `srMode`: авто, только по запросу, выключено); родной мост
   `window.GraniTTS` заменяет `speechSynthesis`, если есть.
2. Без экранного диктора: встроенная речь читает всё сама.
3. Тактильный отклик (`settings.haptics`) на касания и удары, где есть
   вибрация.
Логический слой аудио один на обе платформы: `Bank`, `Spatial`, `Room`,
`Voices`, `Speech` не зависят от устройства.

## §40 брифа «Доступность»: карта жестов переписана под игру

Бриф «Масштабное расширение мира» задавал в §40 свою карту жестов, и она
спорила с действующей. Спор разрешён в пользу игры, а сам §40 переписан:
[`БРИФ-40-ДОСТУПНОСТЬ.md`](БРИФ-40-ДОСТУПНОСТЬ.md) — готовый текст, который
стоит вернуть в бриф вместо прежнего.

Коротко, что заменено и почему:

| было в §40 | стало в игре | почему |
|---|---|---|
| меню действий: 3 пальца × 3 касания | свайп тремя вверх | тройное касание тремя пальцами вслепую почти не ставится; меню должно открываться поверх любого окна одним движением |
| оружие: 3 × 2 достать, 3 × 1 убрать | 3 × 2 переключить | два жеста на одно действие — вдвое больше того, что руке помнить; одиночное касание тремя оставлено пустым, чтобы случайные пальцы ничего не делали |
| 2 × 1 — ближайшие входы/выходы | 2 × 1 — собрать ресурс | сбор нужен на каждом шагу и должен стоить дешевле всего; входы и выходы даёт эхо-скан, и даёт полнее |
| 2 × 2 — закрыть диалог | 2 × 1 — закрыть, если окно открыто | одно правило вместо двух: открыто окно — закроется окно, открыто ничего — соберётся ресурс |
| удержание — непрерывное действие | удержание — ощупывание | для незрячего удержание это главный способ узнать, что под пальцем; непрерывное действие отдано свайпу с удержанием (бег) |
| свайпы — навигация | так и есть | единственное требование, оставленное без изменений |

Спор больше не повторится: любой жест переназначается в настройках, и карту из
прежнего §40 можно собрать себе руками, не трогая кода.

## Переназначение жестов (набор 158)

Карта жестов была вшита в обработчики. Теперь между фигурой и действием
стоит слой привязок.

**`GEST_SHAPES`** — 33 фигуры. Двадцать одна многопальцевая: у каждого из
двух, трёх и четырёх пальцев — одно касание (`tap`), двойное (`tap2`),
тройное (`tap3`) и свайп в четыре стороны. И двенадцать уголков одним
пальцем (`cornerNS`, `cornerWE` и прочие): два шага, второй в другую сторону.

**`GEST_ACTIONS`** — 32 действия, каждое зовёт то, что уже написано в игре:
`handleTwoFingerSwipe`, `handleThreeFingerSwipe`, `handleFourFingerTap`,
`actionMenuGesture`, команды `CMD`. Первое — `none`, «нет команды».

**`GEST_DEFAULTS`** — 15 привязок, в точности прежняя карта жестов.

**`gestRun(пальцы, род, dir)`** — единственная дверь из обработчиков в слой.
Возвращает `true`, только если привязка ОТЛИЧАЕТСЯ от умолчания; иначе
обработчик идёт прежним путём. Поэтому умолчания неотличимы от прежнего
поведения, и сорок наборов про жесты не замечают разницы.

**Распознавание новых фигур.** Счёт касаний подряд доведён до трёх
(`multiTap.c`); уголок отслеживается в `touchmove` по второму шагу от точки
поворота (`gesture.leg1`, `gesture.leg2`) — направление от начала после
поворота даёт диагональ, а не второй шаг. Пока уголок не назначен,
распознаватель ничего не меняет.

**Настройки.** Раздел «Жесты»: у каждой фигуры список из 32 действий,
сгруппированы по числу пальцев, и кнопка возврата к умолчанию. Одно действие
стоит не больше чем на одной фигуре: `gestBind` снимает его со старой.

**Чего нет нарочно.** Фигур с удержанием: удержание занято ощупыванием.

Строка самопроверки — `gestbind`, модуль — `GESTUREBIND`, глава
руководства — 88, набор — 158.

## Разделы длинных окон

Меню действий (130 пунктов), настройки (шесть десятков управляющих элементов)
и руководство (90 глав) разбиты по смыслу, и **заголовок раздела — такой же
пункт окна, как кнопка**.

**Разметка.** Заголовку даются класс `sec-head`, `tabindex="0"` и
`data-cmd="secjump"` — после этого его берёт `visibleInteractive`, а
`activateElement` зовёт `CMD.secjump`. Имя раздела — в `data-sec-title`,
необязательное пояснение — в `data-sec-about`.

**Что слышно.** `secSpeak` собирает: «Раздел «Бой и опасность»: 11 пунктов.
Двойное касание — перескочить к следующему разделу». Число считает `secCount`
— всё между этим заголовком и следующим **в живом окне**, поэтому в бою оно
одно, а в городе другое. `secRefresh(layer)` зовётся на каждой отрисовке.

**Перескок.** `secNav("next"|"prev")` двигает `uiCursor` на следующий или
предыдущий заголовок, по кругу, тем же путём, что и `swipeNav`: сбрасывает
`pendingCursor`, гасит начатое двойное касание, зовёт `setCursor(el,true)`.

**Команды и жесты.** `CMD.secjump`, `CMD.secback`, `CMD.secindex`; действия
жестов `secnext`, `secprev`, `secindex` — по умолчанию не заняты ни одной
фигурой.

**Разбивка.** Меню действий — `AM_GROUPS`, 14 разделов, самый большой на 16
пунктов. Настройки — двенадцать заголовков в разметке `#modal-settings`,
разложенных по семи пунктам (`SET_GROUPS`); заголовок виден, когда открыт его

Руководство — `GUIDE_PARTS`: часть хранит **номера глав из заголовков**, а

## Точность жестов

Все пороги распознавания выводятся из одного множителя `gestK()` (пять
ступеней чуткости, `GEST_SENS`) и одной настройки окна двойного касания
(`tapWindow`). При `gestSens:"norm"` и `tapWindow:800` каждая функция даёт в
точности прежнее число игры.

| функция | при умолчании | что меряет |
|---|---|---|
| `gestSwipePx()` | 38 | порог свайпа, он же предел дрожи для касания |
| `gestMovePx()` | 16 | «палец сдвинулся» одним пальцем |
| `gestMultiPx()` | 45 | перекат многопальцевого тапа |
| `gestMultiMs()` | 1400 | сколько длится многопальцевый тап |
| `gestSwipeMs()` | 1200 | сколько длится свайп |
| `gestTapMaxMs()` | 3000 | сколько длится касание |
| `gestListPx()` / `gestListMs()` | 90 / 700 | когда свайп листает список |
| `gestFastV()` / `gestSlowV()` | 0,55 / 0,25 | «быстро» и «медленно», px/мс |
| `gestHoldMs()` | 250 | ожидание перед называнием под пальцем |
| `gestTapMs()` | 800 | окно двойного касания |
| `gestMultiTapMs()` | 900 | то же для трёх и четырёх пальцев |

**Точность активации.** Пять вещей:

1. Окно двойного касания одно на всю игру: `tapInLayer` и `handleSingleTap`
   берут `gestTapMs()`, прежде это были 800 и 650.
2. Окно отсчитывается от `g.t` (время `touchstart` второго касания), а не от
   `Date.now()` на `touchend`: задержавшийся палец сам съедал своё окно.
3. Второе касание, МЕДЛЕННО съехавшее дальше порога, но оставшееся на
   взведённом пункте (`pendingCursor===взведено||g.ui===взведено`),
   засчитывается как второе, а не переставляет курсор. Быстрый росчерк в те же
   сорок пикселей остаётся перелистыванием — границу двигает чуткость.
4. **Одиночного касания одним пальцем нет.** `tapInLayer` берёт цель только из
   `ensureCursor(lay)` и не зовёт `setCursor` — одно касание не выбирает, не
   называет и не двигает список. Двойное подтверждает выбранный пункт, где бы
   палец ни опустился. Выбор пальцем остаётся отдельным жестом: ветка
   `holdSpoke` в `touchend` (палец полежал ≥ `gestHoldMs()`, элемент назвался)
   ставит курсор и взводит двойное, и она срабатывает раньше `handleSingleTap`.
   Исключение — `settings.fastTap`: там одно касание выполняет то, что под
   пальцем, и это опция, которую игрок включает сам. Вне окон (кнопки на
   игровом экране) курсора нет, и там касание по-прежнему работает по кнопке
   под пальцем.
5. Взвод слышен: `gestArmTick()` — запись `ui_focus` и вибрация 8 мс,
   выключается галочкой `tapTick`.

Строка самопроверки — `gesttune`, модуль — `GESTTUNE`, глава руководства —
91, набор — 161.

## Раздельное касание: жест чтеца экрана (набор 163)

У TalkBack и у VoiceOver есть жест, которым незрячие пользуются каждый день:
палец лежит на пункте и слушает его имя, а второй палец коротко стукает
рядом — пункт выполняется, и рука не отрывается от найденного. Он вернее
двойного касания: попадать по одному и тому же месту дважды, не видя экрана,
трудно, и второе касание часто съезжает.

В игре этого жеста не было. Второй палец на экране означал «два пальца» — то
есть сбор или закрытие окна, — и человек, пришедший из чтеца, вместо
выполнения пункта закрывал окно.

**Как устроено.** `splitArm(t)` взводится в `touchstart` в тот момент, когда
второй палец приходит к одному уже лежащему (`gesture.maxCount===1` — счёт
берётся ДО того, как жест перепишется). `splitFire()` выполняет пункт в
`touchend`, как только второй палец снялся, не дожидаясь отрыва первого:
чтец экрана отвечает тогда же. Отметка `gesture.splitDone` не даёт отрыву
лежавшего пальца вдобавок закрыть окно.

**Условия нарочно узкие**, чтобы обычное касание двумя пальцами не
пострадало:

| условие | зачем |
| --- | --- |
| открыто окно (`navLayer()`) | на поле два пальца собирают ресурс и должны собирать дальше |
| `holdSpoke` | палец пролежал ≥ `gestHoldMs()` и игра успела назвать пункт |
| `lastExploreEl` в этом же слое, жив и не отключён | пункт ещё существует |
| палец всё ещё НА нём (`elementFromPoint`) | ушёл в сторону — жеста нет |
| второй палец пришёл ПОСЛЕ первого | оба разом — это обычное касание двумя |
| не прошло больше `gestMultiMs()` | взвод не живёт вечно |
| `settings.splitTap!==0` | галочка «Раздельное касание» в разделе «Жесты» |

При быстром касании двумя пальцами не выполняется ни одно из первых условий,
и окно закрывается, как закрывалось.

В `GESTURE_MAP` это шестнадцатая запись с родом `split`;
`Gestures.conflicts()` по-прежнему пуст, потому что ключ спора —
`пальцы:род:сторона`, а рода `split` больше ни у кого нет.

**Живая рука.** Набор 163 гоняет всю карту жестов настоящими событиями
устройства (CDP `Input.dispatchTouchEvent`), а не вызовами внутренних
функций, и рука в нём ведёт себя как рука человека: пальцы опускаются
вразнобой по 50–70 мс, перекатываются на 14 пикселей, пока их ставят,
снимаются по очереди с четвертью секунды между ними, свайп идёт вкось на
тридцать градусов и не спеша — семь десятых секунды. Проверяются все
двенадцать многопальцевых свайпов, касания двумя, тремя и четырьмя пальцами,
пятый палец (жест отменяется), отмена касания системой и свайп одним пальцем
в окне во все четыре стороны.

## Фокус не убегает в начало списка (набор 164)

После всякого действия выбор сбрасывался: `activateElement` обнулял
`uiCursor`, `uiCursorLayer` и `pendingCursor`, и следующий свайп начинал
список заново. В окне настроек из сорока с лишним пунктов это значило сорок
свайпов обратно — за каждую снятую галочку, за каждую надетую вещь в
инвентаре, за каждую кнопку меню действий. Ни TalkBack, ни VoiceOver так не
делают: фокус остаётся на том, что вы нажали, а если пункт исчез — переходит
на соседний, на то же место в списке.

**Как устроено.** Перед действием `cursorMark(el)` снимает метку: слой, сам
узел, его ключ (`cursorKey`: `#id`, `cmd:`, `sec:`, `magic:`, `speak:`,
`aria:` или первые шестьдесят знаков текста) и его место в
`cursorItems(слой)`. После действия `cursorRestore(метка)` возвращает выбор
по трём ступеням:

1. тот же узел, если он жив;
2. узел с тем же ключом, если список перестроился и пункт в нём остался под
   другим узлом;
3. то же МЕСТО в списке, если пункт исчез совсем.

Возврат молчалив — своё слово уже сказало само действие. Исключение — третья
ступень: пункт пропал, выбор оказался на другом, и его называют, но с
`interrupt:false`, чтобы не перебить ответ действия.

**Три предохранителя.** Сменился слой (окно закрылось или открылось другое) —
не трогаем ничего, новое окно называет себя само. Действие само подвинуло
курсор — это видно по счётчику `cursorStamp`, который растит `setCursor`, — и
спорить с ним нельзя. Список мог перестроиться не сразу, поэтому возврат
повторяется на следующем такте и ещё раз через шестую долю секунды.

## Касание двумя пальцами — только сбор, закрывает свайп двумя вниз (набор 163)

Касание двумя пальцами делало два разных дела: при открытом окне закрывало
его, на поле собирало ресурс. Для незрячего игрока это худший род жеста —
что он сделает, зависит от того, открыто ли сейчас окно, а окно бывает
открыто незаметно. Вдобавок свайп двумя пальцами вниз над окном не делал
ничего: он упирался в подсказку, которая сама же и советовала «свайп двумя
пальцами вниз — закрыть».

Теперь у каждого жеста одно дело. **Касание двумя пальцами — только сбор**
(`handleTwoFingerTap` → `gatherCurrent("tap")`). **Свайп двумя пальцами
вниз — закрыть открытое окно**, а на поле, когда окон нет, — прежнее
взаимодействие (`handleTwoFingerSwipe("S")`: сперва `activeLayer()` →
`closeTopUI()`, иначе корабль, полёт, `Look.interact()`, `useHere()`).
В диспетчере `touchend` свайп двумя пальцами больше не исключает сторону
`S`, поэтому «вниз» доходит до обработчика, а не проваливается в подсказку.

## Двойное касание — ровно по названному (набор 166)

Было три разных ответа на вопрос «что под пальцем»: `explorePoint` называл
одно множество элементов, фокусом делал другое, поуже, а `touchstart` считал
пунктом третье. Где они расходились, двойное касание уходило мимо
названного. Текст переключателя лежит в `<label>` рядом с флажком — палец
попадал в подпись, фокус оставался на «Назад», и двойное касание закрывало
окно.

Теперь ответ один — `pickTarget(node)` по селектору `PICK_SEL`: подпись
разбирается до своего `label.control`, скрытое и выключенное отбрасывается.
Его зовут и ощупывание, и `touchstart`; `focusableForExplore` — тот же
селектор, поэтому всё названное становится `pendingCursor`. `swipeNav` от
фокуса, которого нет в списке свайпа (строка-подпись), идёт к ближайшему
пункту ниже по `compareDocumentPosition`, а не в начало. В режиме
ощупывания (`body.explore`) окна получают `touch-action:none`, а
`touchmove` гасит прокрутку, если событие отменяемо: список больше не
уезжает под пальцем между первым и вторым касанием.

## Настройки и инвентарь — пунктами (набор 167)

Оба окна двухуровневые, как настройки телефона: первый уровень — список
пунктов, второй — содержимое одного пункта.

**Настройки.** `SET_GROUPS` — семь пунктов: `sound` (что звучит, громкость,
объёмный звук и живой мир), `tts` (синтезатор речи), `speech` (голос
рассказчика, что игра говорит сама), `ui` (доступность и касания, субтитры),
`gest` (жесты, точность жестов), `diff`, `save`. Разметка: `#setMenu` со
списком `#setMenuList` (кнопки рисует `buildSetMenu` из `SET_GROUPS`, у
каждой `data-cmd="setgroup:<id>"`, `data-punkt`, `data-punkt-title` и
`data-speak` с числом разделов и настроек — `setGroupCount` считает по
разметке, а не по видимости) и `#setOne` с группами
`.set-group[data-set-group]`, внутри которых прежние заголовки `sec-head`.
`setGroupOpen(id)` прячет чужие группы, в пункте из одного раздела прячет и
заголовок, и строку перескока `#setSecRow`, зовёт `secRefresh`, ставит выбор
на первый пункт и называет пункт. `setShowMenu(от)` возвращает список и
ставит выбор на пункт `от`. Кнопка «Назад» в шапке во втором уровне
получает `data-speak="Назад: ко всем пунктам настроек."` (`setBackLabel`).
Команды: `CMD.settings(g)` — без довода список, с доводом сразу пункт;
`CMD.setgroup`, `CMD.setgroups`. Модуль — `SETTINGS_MENU`.

**Инвентарь.** Состояние — `INV.cat`. `renderInventory` без раздела рисует
все шестнадцать `INV_SECTIONS` на своих местах (с набора 171) (`data-cmd="invcat:<id>"`, пустые — «пусто»,
полные — `invCatSummary`: «2 вещи» или «2 вида, всего 6 штук»); с разделом —
его вещи между двумя кнопками `invcats`. `invOpenCat(id)` и `invBack()`
снимают выбор вещи (`INV.sel`): он принадлежит открытому разделу. Свайп
одним пальцем вверх или вниз открывает действия только внутри раздела; в
списке разделов он листает, как в любом окне.

**Назад.** `closeTopUI` спрашивает верхнее окно стопки: у настроек —
`setBack()`, у инвентаря — `invBack()`; только если они вернули `false`
(уже в списке), окно закрывается. Так работают и «Назад», и свайп двумя
пальцами вниз, и Эскейп. `openModal` зовёт `modalOpenReset(id)`: каким бы
путём окно ни открыли, оно начинается со списка.

**Разбор по родам.** Двадцать первый род — `treasure` (в котомке он лежит в разделе «Артефакты»): именные находки
`VAULT_TREASURES`, `DEEP_EVENTS`, `DEEP_COMPLEX` (`invTreasureNames`) и
трофеи `WORLD_BOSSES` (`invBossTrophies`). Цена сокровища — половина его
меры (`invTreasureInfo`), покупают `redk`, `arte`, `star`, `zapret`, `kamni`,
`obshiy`; в лавке у него свой раздел `SHOP_CATS`. Правила `INV_CAT_RULES`
пишут границу слова как `(?:^|[^а-яё])…(?![а-яё])`: `\b` в JavaScript знает
только латиницу. Сырьё: `INV_RAW` (с шкурой), органы, кровь и яд твари —
`INV_ALCH` → ингредиенты, сорта трав, грибов и ягод — `invHerbGoods` →
ингредиенты. Вещи Пути (`PATH_ART_BY_NAME`) — магические, маска Пути —
аксессуар. Вещь Дома получает род и место по имени (`gearTypeByName`) при
покупке, а в старом сохранении — при первом показе. Вложенные чары
(`G.charged`) — строки рода `charged` в свитках и магических предметах; у
действия может быть поле `kinds`, и строке `charged` достаются только
действия с `kinds:["charged"]` (`chargeuse`, `chargerefill`) и общие
«Осмотреть» и «Выбросить».

Строка самопроверки — `punkty`, глава руководства — 93, набор — 167.

## Котомка из шестнадцати разделов и тринадцать мест на теле (набор 171)

**Род и раздел.** Род вещи (`INV_CATS`, двадцать один, `invCategoryOf`) нужен
ремеслу, торгу и цене и остаётся как был. Раздел котомки — один из
шестнадцати `INV_SECTIONS` (`weapon`, `armor`, `helm`, `gloves`, `boots`,
`ring`, `bracelet`, `amulet`, `artifact`, `consumable`, `potion`, `res`,
`material`, `tool`, `quest`, `other`); у каждого `n`, значок `з` и `о` — что
в него ложится (его говорит пустой раздел). `invSectionOf(row)`: снаряжение —
по месту на теле (`gearSectionOf`), вложенная чара — свиток в расходники,
остальное — в артефакты, украшение-строка — по слову в имени, всё прочее —
по таблице `INV_SECTION_OF_CAT`. Единственная вещь или вещь Дома, которую
носят на шее, но зовут не амулетом (`AMULET_RE`), лежит в артефактах.
`invAll()` кладёт в каждую строку `раздел` (и `место` у снаряжения),
`renderInventory` и `invOpenCat` работают с разделами; старые команды с
родом (`invcat:treasure`) ведёт в раздел `invSectionId`. `Inventory.registerCat`
принимает четвёртым доводом раздел.

**Места.** `EQUIP_PLACES` — тринадцать мест: `weapon`, `shield`, `helm`
(голова), `ears` (уши), `amulet` (шея), `cloak` (плечи), `armor` (торс),
`gloves` (руки), `bracelet` (запястье), `ring` и `ring2` (пальцы левой и
правой руки), `belt`, `boots` (ноги). У места `где`, `куда`, `вес`
(доля числа вещи в защиту и удар) и `тело` (в бою не меняют).
`equipPlaceOf(it)` решает место по роду (`gearCat`) и слову в имени;
`equipPlacesFor` даёт кольцу оба пальца. `it.slot` остаётся классом вещи
(`weapon`/`armor`/`acc`) для добычи, отделки и лавок. Роды находок
`ITYPES` — тринадцать, с перчатками, сапогами, браслетом и серьгами; род
слова «мн» у `QUAL_R` и `MAT_R`. Переделы `pr_gloves` и `pr_boots` в
кожевенной яме делают перчатки и сапоги своей работы.

**Что даёт надетое.** `equipBonus("def"|"atk")` входит в `def()` и `atk()`;
`EQUIP_GIFTS` — своё у места через характеристики артефактов (`ART.sum`
прибавляет `equipStat`) и производную `carry` (`derived`). Мера вещи —
`equipMeasure` (ранг и качество), материал — `equipMaterial`; вещь в
состоянии ниже тридцати даёт всё вполсилы (`equipWearK`). Щит —
`shieldBlockChance`: в ходе твари удар делится пополам, звучит
`oc_shield_metal` или `oc_shield_wood`, щит теряет единицу состояния.
`stepProfile` слушает сапоги (`p.boots`), зона `cold` в `Zones.step` без
плаща тратит воду, `gearWear` изнашивает оружие и одну из надетых вещей
брони, `gearTrait` смотрит все места. `equipGiveText` называет прибавки
словами, `invWornText` — всё надетое (строка `#invWorn` и карточка героя).

**Меню.** `invActionsAll` возвращает `ok` и `blocked`; в окно идёт только
`ok` (`invActions`), `blocked` помнится для `invWhy` и проверок. У действия
может быть `имя(row,ctx)` — подпись по обстановке («Надеть вместо: …»).
Снаряжение: `equip` (оружие), `wear` и `wear2` (второе кольцо), `unequip`,
`draw`, `sheathe`, `compare` (`invCompareWith` — с надетым на то же место).
`В_БОЮ` — что остаётся в бою (`invContext().бой`). `invSelFromCursor`
выбирает вещь под фокусом, поэтому свайп вверх открывает действия без
двойного касания. `invDo` помнит вещь (`invTrack`) и после действия
возвращает на неё фокус (`invRefocus`), даже если она сменила строку;
каждое действие сохраняет игру.

**Старые сохранения.** `normalizeEquip()` (из `normalizeWeaponState`)
разносит прежнее место `acc` и шлем или щит из `armor` по своим местам, а
при занятом месте кладёт вещь в суму; надетое не лежит в суме второй раз.
Самопроверка — строка `inv16`; руководство — глава 94.

## Меню действий — пунктами (набор 172)

**Разделы.** `AM_GROUPS` — шестнадцать записей `[имя, пункты, {id, з, о}]`:
`start`, `here`, `move`, `fight`, `hero`, `quests`, `craft`, `people`,
`magic`, `faith`, `books`, `world`, `realms`, `dark`, `sound`, `game`;
`AM_GROUP_BY_ID` — по `id`. Пункты прежние (130, подписи те же), каждый ровно
в одном разделе; уместность решает `amAvailable`, подпись — `amBtnLabel`.

**Окно.** `openActionMenu(группа?)` строит в `#amList` два блока: `#amMenu`
(кнопки разделов `data-cmd="amgroup:<id>"`, `data-punkt`, `data-speak` с
числом уместных пунктов и `о`; в бою первой — `am:flee`; последней —
`am:close`) и `#amOne` (кнопки `amgroups` сверху и снизу, подсказка
`#amOneHint` и по `.am-group[data-am-group]` на раздел со всеми его
уместными пунктами). Раздел без уместных пунктов в `#amMenu` не попадает.
Скрытые разделы остаются в разметке — как настройки чужих пунктов.
`amGroupOpen(id)` показывает один раздел и ставит выбор на первый пункт,
`amShowMenu(от)` возвращает список с выбором на `от`, `amBack()` — шаг назад
(в списке — `false`). `closeTopUI` и Эскейп сперва зовут `amBack()`, и только
из списка закрывают меню; `closeActionMenu` сбрасывает `AMG.open`. Команды:
`CMD.amgroup(id)`, `CMD.amgroups()`, `CMD.menu(id)` (меню сразу на разделе).
Заголовков-перескоков в меню больше нет; в настройках и руководстве они
остаются. Самопроверка — строка `ampunkty`; руководство — глава 95.
