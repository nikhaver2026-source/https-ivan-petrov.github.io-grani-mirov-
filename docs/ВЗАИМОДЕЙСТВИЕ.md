# Единая система взаимодействия «Грани Миров»

Документ описывает, как устроено взаимодействие игрока с миром после
переработки по брифу «Система звуковой навигации, жестов, инвентаря,
торговли и интерактивных объектов». Главный принцип: игрок не угадывает,
какой интерфейс предусмотрел разработчик — мир сам даёт логичный набор
действий по ситуации. Проверяется набором 104 (`tests/`); прежние свойства —
наборами 27, 29, 37, 41, 42, 68, 95, 97.

## 1. Режим полной звуковой игры

Настройка «Подсказки расположения объектов» (`settings.hintMode`):

| Режим | Что делает |
|---|---|
| `full` — полные | игра называет, что рядом, где оно и как подойти |
| `min` — минимальные | описания места и пространственные сведения режутся до первой фразы (`Speech._shape`), объекты — только по запросу |
| `sound` — только звуковая навигация | словесные подсказки о расположении выключены (`settings.hints=0`, распорядитель отбрасывает `desc` и `object`); мир слышен |

Старый ключ `settings.hints` выводится из режима, так что прежний код читает
его как раньше. В режиме звука проходы слышны ветром с их стороны
(`passageCues`), дверь — петлёй, ступени — камнем, ворота — створкой; живая
звуковая картина `Scape` подаёт голоса колодца, горна, алтаря, лавки, книг,
тварей и жителей с их сторон (`SCAPE_TILE`, `SCAPE_VOICE`). У каждого
источника — сторона, расстояние, высота, громкость с затуханием, отзвук
места (`Room`) и преграды стен (`Spatial.occlusion`). Тварь и житель
звучат шагом, дыханием и делом со своей стороны.

## 2. Осмотр

`Look` (модуль `LOOK`), три пальца влево. Сторона взгляда — сторона
последнего шага (`lastMoveDir`). `Look.scan()` находит объекты, жителей,
двери, проходы, лестницы, ресурсы, находки, обозы, узлы сети, ловушки и
тварей; каждому — сектор относительно взгляда (`впереди`, `слева`,
`справа`, `позади`, `здесь`), опасное — первым. `Look.summary()` говорит
коротко: что, сторона, шаги. Окно осмотра — список; двойное касание по
объекту — `Look.select()`: под рукой (по прямой, не по диагонали) сразу
открываются его действия, дальше объект становится целью (`Look.target`).

## 3. Жесты

Все касания идут через один диспетчер (`touchstart`, `touchmove`,
`touchend`), один обработчик кликов и один клавиатуры — набор 104
пересчитывает их в исходнике. Опись жестов — таблица `GESTURE_MAP`
(модуль `Gestures`): число пальцев решает первым, у каждой записи — род,
сторона, где действует и приоритет; `Gestures.conflicts()` пуст. Окно
«Жесты» читает эту же таблицу.

- Два пальца вниз — `Look.interact()`: цель под рукой → её действия; цель
  дальше → направление, шаги и маяк; цели нет → `useHere()`.
- Два пальца вверх — повторить последнее; если речь идёт — оборвать
  (`Speech.isSpeaking` → `stop`, иначе `repeatLast`); два запуска речи не
  складываются.
- Два пальца влево — карта места, и снаружи тоже: сетка семь на семь и
  «Известные точки» (`mapPoints`) — двери, лестницы, жители, сундуки внутри;
  города, постройки, подземелья, цели дел, узлы сети, крепости, зал Дома
  снаружи; касание точки — маяк с её стороны. Тот же жест закрывает.
- Два пальца вправо — журнал дел по разделам: активные, готовые к сдаче,
  выполненные, проваленные, цепочки, скрытые; у дела — цель
  (`qProgressText`), этап, указания, награда, последствия
  (`questConsequences`). Тот же жест закрывает.
- Касание игрового поля одним пальцем — одиночное или двойное — ничего не
  делает: сбор — касание двумя пальцами, действие здесь — два пальца вниз.

## 4. Инвентарь

Три пальца вниз. Двадцать разделов (`INV_CATS`): оружие, щиты, броня,
шлемы, перчатки, обувь, аксессуары, артефакты, магические предметы, свитки,
книги, зелья, ресурсы, материалы, квестовые предметы, инструменты,
боеприпасы, еда, ингредиенты, прочие предметы. Раздел вещи решают правила
`INV_CAT_RULES` по порядку (`invCategoryOf`); хранилище сохранения (`G.gear`,
`G.items`, `G.inv`, `G.potions`, `G.artifacts`, `G.comps`) на раздел не
влияет. `Inventory.registerRule(cat,re)` и `Inventory.registerCat(id,n,з)`
расширяют разбор без правки кода.

Карточка (`invBrief`): имя, род («одноручное оружие», «щит», «доспех»…),
урон или защита, состояние в сотых (`itemCondition`, поле `сост`),
требование силы (`itemStrReq`), ранг и качество, надето ли, чары, руна,
освящение, яд, клеймо, улучшения. Бой снимает состояние (`gearWear` в
`victory`), наковальня возвращает.

## 5. Действия вещи

Реестр `ITEM_ACTIONS` (`iaction(id,{n,значок,cats,можно,делать})`). `можно`
возвращает `true` или причину словами; `invActionsAll(row)` даёт доступное
и недоступное с причиной, окно показывает оба списка (недоступных — не
больше восьми, сперва те, что упираются не в место). Контекст — `invContext()`:
станки рядом (`objectsHere` с полем `станок`), алтарь (`altarAt`),
торговец, житель, ночь.

| Раздел | Действия | Контекст |
|---|---|---|
| снаряжение | осмотреть, экипировать, снять, использовать, сравнить, состояние, продать, выбросить | наковальня/горн: ремонт (руда), улучшить (слиток, до трёх), закалить, заточить, перековать, клеймо, компонент, разобрать, ковать; круг/шар: зачаровать (кристалл); верстак/наковальня: руна (камень) |
| артефакты | осмотреть, изучить, активировать, деактивировать (спящий не действует — `ART.works`), настроить, способность (заряд), определить свойства, зарядить, зачаровать, починить, продать, выбросить | |
| ресурсы, материалы, ингредиенты | осмотреть, использовать, разделить стопку (на землю, `G.piles`), объединить, применить в ремесле (техники станка, берущие этот припас), продать, выбросить | чан: алхимия, смешать, эссенция, яд (грибы ×2), противоядие (трава ×2), очистить, исследовать состав; горн: плавить; наковальня: клинок; алтарь: дар, жертва |
| свитки, книги | осмотреть, прочитать, изучить, изучать главы, использовать для обучения (заклинание из книги), передать жителю, продать, выбросить | |
| зелья, еда | выпить, съесть, передать, продать, выбросить | |
| квестовые | осмотреть; выбросить и продать защищены — причина словами | алтарь: возложить реликвию |
| алтарь (любой раздел) | помолиться, обратиться к божеству, откровение (благосклонность ≥ 12), освятить (≥ 4), очистить, снять проклятие, особый ночной ритуал (≥ 20, ночь, артефакт) | |

«Выбросить»: вещь — «Выбросить «X»? Да / Нет»; стопка — «Выбросить сколько?
Одну / Несколько / Половину / Всю стопку / Нет». Квестовые предметы
защищены. Продажа из инвентаря — «Продать «X» за N золотых? Продать /
Отмена».

## 6. Интерактивные объекты

Одна архитектура: объект (`objectsHere`) → действия (`IACT`, `actionsFor`,
`actionsForAll` с причинами) → окно (`openObjActions`) → исполнитель
(`doObjAction`); всё это — модуль `Interact` (`INTERACTION`): `objects`,
`describe`, `actions`, `menu`, `run`, `why`, `register`. У действия — `можно`
и `почему`; область уместности причин — `IACT_SCOPE`. Помимо прежних
(осмотреть, прислушаться, постучать, пустота, отсек, тайники, ящик,
механизм двери, рычаг, сдвинуть, полка, техники станков, двенадцать
действий алтаря, ловушки) добавлены:

- дверь: открыть, закрыть, запереть, отпереть, ключ, взломать, чары,
  подслушать (что за створкой: `behindDoor`); запертая дверь держит шаг
  (`moveInside`);
- сундук: открыть, осмотреть содержимое (`chestPreview`), забрать всё,
  ключ, взломать; с третьего яруса часть сундуков заперта (`chestLocked`);
- шкаф и полка: найти книгу, читать, взять книгу (в раздел книг, `G.tomes`),
  перебрать полку, тайник, механизм;
- стол, конторка, комод, стойка: взять предмет, читать документы, ящик,
  тайник;
- колодец: набрать воды, бросить монету (удача), прислушаться, спустить
  верёвку;
- очаг и жаровня: отдохнуть, приготовить, зажечь факел;
- статуя: прочитать надпись; круг: встать в круг; лестница: спуститься или
  подняться, послушать вниз; прилавок: торговать, спросить цены; узел
  сети: сведения; постройка: войти, услуги, причал, скакун; ресурс: собрать.

Звук у каждого действия — записью (`doorSound`, `chestSound`, `bookSound`,
`altarSound`, банк ролей), со стороны объекта.

## 7. Торговля

Модуль `Trade` (`TRADE`), окно `modal-shop`, открывается из карточки
торговца («Торговля: купить и продать»), из меню действий («Торговля с
ближним торговцем») и с прилавка внутри стен. Два раздела: «Купить» —
`shopStockRows` из `stockFor` (специализация `MERCH_KINDS`, нрав, казна,
скрытый товар `merchDoors` с условием); «Продать» — `shopSellRows` из
инвентаря, что торговец согласен взять (`merchantBuys` по таблице
`MERCH_BUYS`: кузнец — оружие и металл, травник — травы и зелья, книжник —
книги и свитки, собиратель — артефакты; «берёт только своё» сужает,
«берёт краденое» расширяет; кошель торговца конечен). Пятнадцать
категорий (`SHOP_CATS`). Карточка: имя, категория, характеристики,
состояние, ранг, качество, цена, счёт, требование силы, доступность.
Сделка подтверждается: «Купить «X» ×N за M золотых? Купить / Отмена»;
стопки — счётом (1, 5, 10, на всё золото / всё). Старые кнопки прилавка в
карточке жителя остались как короткий путь.

## 8. Речь и субтитры

Один распорядитель речи (`Speech`): смена пункта обрывает старое
(`interrupt:true`), один и тот же элемент не называется дважды подряд,
меню читает доступное списком и число недоступного. Субтитры —
`settings.subMode`: `off`, `important` (события), `speech` (реплики),
`sounds` (и описания записей, `subSound`, раз в девять десятых секунды);
`sub(text,level)` — уровни `important`, `speech`, `sound`. Речь попадает в
субтитр из `Speech._speak` по приоритету. Субтитры не обязательны для
прохождения.

## 9. Критерий готовности

Найти объект по звуку → осмотреться (3←) → выбрать объект (двойное
касание) → контекстное меню (2↓ или сразу) → действия свайпом → выбрать
(двойное касание) → результат словом и звуком → назад в мир (2-пальцевое
касание закрывает). Инвентарь: 3↓ → раздел → вещь → карточка → действия
(свайп ↑/↓) → результат. Торговля: карточка торговца → «Торговля» →
«Купить» или «Продать» → категория → вещь → карточка и цена → сделка.
Объект: действие → проверка условий → выполнение или причина отказа.

## 10. Что проверяется автоматически и что — руками

Наборы 104, 27, 29, 37, 41, 42, 68, 95, 97 в настоящем браузере
проверяют: единственность обработчиков в исходнике, карту жестов без
споров, инертность касаний поля одним пальцем, работу жестов поверх окон,
речь без двойного озвучивания (один распорядитель, `speakTextOf` не
называет один элемент дважды), режим «только звук» (описания молчат,
проходы слышны), инвентарь и торговлю целиком, объекты с причинами отказа.

Руками, на устройстве, проверяются то, чего браузер без экрана не даёт:
1. Android с TalkBack и iOS с VoiceOver: жесты игры перехватываются в
   режиме прямого касания (настройка «Объявления VoiceOver и TalkBack» —
   `srMode`: авто, только по запросу, выключено); родной мост
   `window.GraniTTS` заменяет `speechSynthesis`, если есть.
2. Без экранного диктора: встроенная речь читает всё сама.
3. Тактильный отклик (`settings.haptics`) на касания и удары, где есть
   вибрация.
Логический слой аудио один на обе платформы: `Bank`, `Spatial`, `Room`,
`Voices`, `Speech` не зависят от устройства.

## Переназначение жестов (набор 158)

Карта жестов была вшита в обработчики. Теперь между фигурой и действием
стоит слой привязок.

**`GEST_SHAPES`** — 33 фигуры. Двадцать одна многопальцевая: у каждого из
двух, трёх и четырёх пальцев — одно касание (`tap`), двойное (`tap2`),
тройное (`tap3`) и свайп в четыре стороны. И двенадцать уголков одним
пальцем (`cornerNS`, `cornerWE` и прочие): два шага, второй в другую сторону.

**`GEST_ACTIONS`** — 32 действия, каждое зовёт то, что уже написано в игре:
`handleTwoFingerSwipe`, `handleThreeFingerSwipe`, `handleFourFingerTap`,
`actionMenuGesture`, команды `CMD`. Первое — `none`, «нет команды».

**`GEST_DEFAULTS`** — 15 привязок, в точности прежняя карта жестов.

**`gestRun(пальцы, род, dir)`** — единственная дверь из обработчиков в слой.
Возвращает `true`, только если привязка ОТЛИЧАЕТСЯ от умолчания; иначе
обработчик идёт прежним путём. Поэтому умолчания неотличимы от прежнего
поведения, и сорок наборов про жесты не замечают разницы.

**Распознавание новых фигур.** Счёт касаний подряд доведён до трёх
(`multiTap.c`); уголок отслеживается в `touchmove` по второму шагу от точки
поворота (`gesture.leg1`, `gesture.leg2`) — направление от начала после
поворота даёт диагональ, а не второй шаг. Пока уголок не назначен,
распознаватель ничего не меняет.

**Настройки.** Раздел «Жесты»: у каждой фигуры список из 32 действий,
сгруппированы по числу пальцев, и кнопка возврата к умолчанию. Одно действие
стоит не больше чем на одной фигуре: `gestBind` снимает его со старой.

**Чего нет нарочно.** Фигур с удержанием: удержание занято ощупыванием.

Строка самопроверки — `gestbind`, модуль — `GESTUREBIND`, глава
руководства — 88, набор — 158.

## Разделы длинных окон

Меню действий (130 пунктов), настройки (шесть десятков управляющих элементов)
и руководство (90 глав) разбиты по смыслу, и **заголовок раздела — такой же
пункт окна, как кнопка**.

**Разметка.** Заголовку даются класс `sec-head`, `tabindex="0"` и
`data-cmd="secjump"` — после этого его берёт `visibleInteractive`, а
`activateElement` зовёт `CMD.secjump`. Имя раздела — в `data-sec-title`,
необязательное пояснение — в `data-sec-about`.

**Что слышно.** `secSpeak` собирает: «Раздел «Бой и опасность»: 11 пунктов.
Двойное касание — перескочить к следующему разделу». Число считает `secCount`
— всё между этим заголовком и следующим **в живом окне**, поэтому в бою оно
одно, а в городе другое. `secRefresh(layer)` зовётся на каждой отрисовке.

**Перескок.** `secNav("next"|"prev")` двигает `uiCursor` на следующий или
предыдущий заголовок, по кругу, тем же путём, что и `swipeNav`: сбрасывает
`pendingCursor`, гасит начатое двойное касание, зовёт `setCursor(el,true)`.

**Команды и жесты.** `CMD.secjump`, `CMD.secback`, `CMD.secindex`; действия
жестов `secnext`, `secprev`, `secindex` — по умолчанию не заняты ни одной
фигурой.

**Разбивка.** Меню действий — `AM_GROUPS`, 14 разделов, самый большой на 16
пунктов. Настройки — десять заголовков прямо в разметке `#modal-settings`.
Руководство — `GUIDE_PARTS`: часть хранит **номера глав из заголовков**, а
`guideOrder()` даёт порядок чтения, по которому ходят «Пред.» и «След.».

Строка самопроверки — `sections`, модуль — `SECTIONS`, глава руководства —
90, набор — 160.

## Точность жестов

Все пороги распознавания выводятся из одного множителя `gestK()` (пять
ступеней чуткости, `GEST_SENS`) и одной настройки окна двойного касания
(`tapWindow`). При `gestSens:"norm"` и `tapWindow:800` каждая функция даёт в
точности прежнее число игры.

| функция | при умолчании | что меряет |
|---|---|---|
| `gestSwipePx()` | 38 | порог свайпа, он же предел дрожи для касания |
| `gestMovePx()` | 16 | «палец сдвинулся» одним пальцем |
| `gestMultiPx()` | 45 | перекат многопальцевого тапа |
| `gestMultiMs()` | 1400 | сколько длится многопальцевый тап |
| `gestSwipeMs()` | 1200 | сколько длится свайп |
| `gestTapMaxMs()` | 3000 | сколько длится касание |
| `gestListPx()` / `gestListMs()` | 90 / 700 | когда свайп листает список |
| `gestFastV()` / `gestSlowV()` | 0,55 / 0,25 | «быстро» и «медленно», px/мс |
| `gestHoldMs()` | 250 | ожидание перед называнием под пальцем |
| `gestTapMs()` | 800 | окно двойного касания |
| `gestMultiTapMs()` | 900 | то же для трёх и четырёх пальцев |

**Точность активации.** Пять вещей:

1. Окно двойного касания одно на всю игру: `tapInLayer` и `handleSingleTap`
   берут `gestTapMs()`, прежде это были 800 и 650.
2. Окно отсчитывается от `g.t` (время `touchstart` второго касания), а не от
   `Date.now()` на `touchend`: задержавшийся палец сам съедал своё окно.
3. Второе касание, МЕДЛЕННО съехавшее дальше порога, но оставшееся на

   пальцем, и это опция, которую игрок включает сам. Вне окон (кнопки на
   игровом экране) курсора нет, и там касание по-прежнему работает по кнопке
   под пальцем.
